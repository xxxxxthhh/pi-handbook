§1 为什么写这本

上游已经有 32945 行 markdown 了

earendil-works/pi 自带 97 个 markdown 文件、共 32945 行文档，写得比多数开源项目都好。所以本书不复述文档。它的全部价值来自三件文档做不到的事：

  • 读代码而不是读 README。每个关于行为的断言都锚定到 path:line，并且有校验器逐条核对该行的实际内容。
  • 区分「已发布」与「设计文档」。上游正在做一次 agent harness 重写。文档描述的系统和你机器上跑的系统不是同一个——本书为每章标注实现状态，并给出判定证据。
  • 记录文档与代码的漂移。一个 5565 commits / 286 位作者 / 32945 行自有文档的仓库，drift 必然存在，且没人写下来过。

一句话预告全书最重要的发现：那份 3437 行的 durable harness 设计文档描述的执行器，在锚定版本上有 22 个方法直接抛错，且没有任何生产代码路径构造它。真正在跑的是另一个循环。判定过程见 第 08 章。

§2 实现状态标记

三种徽章，每章头部一个

徽章含义判定方式
已发布该章描述的代码在 HEAD 上被 packages/coding-agent 实际执行从生产入口的构造点追调用链
部分落地类型/接口/测试已存在，但主要操作路径仍抛错或未接线指出抛错点或未接线证据
仅设计文档只存在于 docs/*.md，代码中无对应实现grep 无实现

每个徽章在 data/status.json 里有对应条目，含 path:line 证据；校验器会核对页面徽章文案与该文件一致，且每条证据指向的行确实包含预期内容。徽章不是印象，是可核对的判定。

§3 怎么核对本书

锚定版本

本书锚定的上游版本固定不变
repo:  https://github.com/earendil-works/pi
SHA:   ac4ac9eaf69f2b01ca3af984a5c48f3b99b84278
date:  2026-08-07
速度:  约 428 commits/月
以每月 428 次提交的速度，不锚定 SHA 的行号引用在一周内就会失效。本书全部 ↪ path:line 链接都指向该 SHA 的 blob，点开即是当时的原文。

三张辅助页

  • 溯源索引——全站每条引用的汇总表，按文件分组。想批量核对从这里开始。
  • 漂移记录——文档与代码不一致之处，每条双向举证（文档侧 + 代码侧各一个 path:line）。
  • 术语表——英文术语 → 中文解释 → 首次出现章节。

两种代码块，标签不同

标签含义
原文 L582–L584逐字摘自该行区间。可能并置多个不连续区间（会写明）
改写自 L167–L274为讲解压缩过：合并行、省略参数。脚注会说明改了什么

这个区分是硬性的。本书的前提是「我们读代码」，把改写过的块标成「节选」是唯一不可犯的错。

§4 不覆盖什么
  • pi 的使用教程。上游 docs/quickstart.md 已足够，本书不重复。
  • 逐个 provider 的接入细节。第 09 章只讲抽象的形状与代价，不讲 39 家各自怎么接。
  • TUI 的完整 API 与渲染正确性审计。第 11 章讲为什么自研，不讲怎么用。
  • 写扩展的 step-by-step。第 12 章讲能改什么、边界在哪，教程看上游 docs/extensions.md。
  • 端到端行为验证。本书读代码，没有运行 pi 做行为观察。完整的自我边界见 第 20 章 §4。
